2.2.10.   Perancangan Basis Data Relasional

Setelah seluruh aliran fungsional aplikasi dan aktivitas pengguna selesai dipetakan, perancangan berlanjut pada tahap desain data. Pada tahap desain data ini, model relasional digunakan untuk mengelola informasi secara terstruktur melalui tabel-tabel yang saling terhubung guna menjamin integritas data persediaan suku cadang kelistrikan [19]. Pemodelan data logis ini diawali dengan pembuatan Entity Relationship Diagram (ERD) untuk memvisualisasikan hubungan abstrak antar-entitas beserta atribut pendukungnya di dalam basis data [19]. Rancangan ERD tersebut kemudian diwujudkan secara konkret ke dalam tingkatan fisik berbentuk Physical Data Model (PDM). PDM berfungsi untuk memetakan arsitektur penyimpanan riil pada MySQL, yang mencakup penentuan tipe data spesifik (seperti varchar, int, decimal, atau datetime), penerapan kunci utama (Primary Key) sebagai identifikasi unik data barang, serta kunci tamu (Foreign Key) untuk mengunci hubungan kardinalitas antar-tabel (One-to-Many) agar terhindar dari anomali data. Implementasi teknis dari skema fisik PDM tersebut selanjutnya dieksekusi menggunakan perintah kueri Structured Query Language (SQL). Pengelolaan data ini mencakup Data Definition Language (DDL) untuk membangun struktur fisik database electrical_system, serta Data Manipulation Language (DML) untuk mengolah informasi mutasi stok barang [19]. Dalam mendukung pendekatan Queue-Based Processing, kueri SQL tersebut memanfaatkan klausul pengondisian khusus melalui perintah ORDER BY yang dikombinasikan dengan fungsi urutan waktu kedatangan terkecil (timestamp ASC) [20]. Logika kueri terurut ini sangat vital agar mesin database secara otomatis dapat menyaring dan menunjuk rekaman batch barang paling lama untuk dipotong terlebih dahulu, sehingga sistem mampu mengeksekusi metode First-In-First-Out (FIFO) secara konsisten, aman, dan real-time.
